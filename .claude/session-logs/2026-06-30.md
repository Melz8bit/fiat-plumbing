## Work Done

### Supabase RLS — Enable on company_documents
- Received Supabase security email flagging `rls_disabled_in_public` on the `FiatPlumbing` project
- Used Supabase MCP `get_advisors` + `list_tables` to diagnose:
  - **Critical (ERROR):** `public.company_documents` had RLS disabled — anyone with the Supabase anon key could read/write/delete all rows via the REST API
  - **Info (INFO):** All other 31 tables had RLS enabled but no policies — correct behavior for this app (direct PostgreSQL connection bypasses RLS; REST API access fully blocked)
- Applied migration: `ALTER TABLE public.company_documents ENABLE ROW LEVEL SECURITY;`
- Verified advisory cleared — no remaining ERROR-level security issues
- No policies needed since the app connects via direct PostgreSQL connection (postgres superuser), which bypasses RLS entirely. The app is unaffected.
